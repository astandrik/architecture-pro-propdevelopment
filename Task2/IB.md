# Проверочный лист безопасности бизнес-систем PropDevelopment

## Обоснование выбора разделов

Раздел «Управление доступом» идёт первым, потому что проблема уже проявляется на практике: клиенты видят чужие ФИО в личном кабинете, а партнёрские API позволяют одной управляющей компании читать данные другой. Аутентификация разнесена между Keycloak и двумя экземплярами AD, интеграция между ними не описана.

«Безопасность данных» включена потому, что именно с ней связаны обе главные проблемы компании: «Нарушен контроль данных» и «Есть проблемы с API партнёров». Клиентов регистрируют в нескольких точках без координации, внутренние потоки между продуктами никто системно не контролирует, ограничений на доступ к данным со стороны систем обработки нет. Нет уверенности, что бизнес-процессы соответствуют законодательным нормам.

«Защита инфраструктуры» нужна из-за гибридного ландшафта: собственный ЦОД, приватное облако, арендованные мощности. Внешний трафик идёт через firewall, но из описания непонятно, как устроены внутренняя сегментация и защита облачной части.

«Управление инцидентами» — компания готовится к первому аудиту после утечки у конкурента. Регулярных регламентов реагирования на инциденты пока нет.

«Специфические аспекты» включены выборочно: мобильное приложение для собственников и собственный ЦОД требуют отдельной проверки мобильного доступа и физической безопасности.
